PLAN — VideoPsalm Rust: brightness + animation not working

1 · Verdict

Both controls were stored but never rendered. The model (cascade/style) was correct; the render paths dropped the values on the floor. Two independent bugs, one class: state that silently stops meaning what the UI claims.

2 · Root cause — brightness

Root::projector_snapshot resolves luminosity for Image and VideoLoop chains correctly — but the compositing overlay that actually grades the pixels was gated on matches!(snap.bg_kind, BackgroundKind::Image) in two places: projector_window::render_snapshot and the in-window room mirror in main.rs. Result: with a video background, moving Luminosité updated the cascade, repainted, and changed nothing on screen. Images worked; videos never did.

3 · Root cause — animation

The Animation ribbon wrote style.transition (+ layout prefs) and every render path ignored it: ProjectorSnapshot didn't even carry a transition field, and grep transition projector_window.rs returned zero hits. Selecting fade/slide/zoom stored a value and rendered a hard cut, forever. GPUI 0.2.2 also has no CSS-transition equivalent, so there was never a mechanism — only a stored string.

4 · Fix (scratch: work/tmp-brightfix/)

FileChange
projector_window.rsnew grades_luminosity_overlay() (Image | VideoLoop); overlay gate uses it; new transition snapshot field; new apply_transition() — 450 ms oneshot entrance via with_animation keyed on item+slide+transition (fade = opacity; slide += x-settle; zoom = pad-settle, no scale primitive in gpui 0.2.2 — stated in code)
main.rssnapshot carries self.transition; room mirror uses the shared overlay helper
presentation.rsempty() snapshot gets transition: "none"
